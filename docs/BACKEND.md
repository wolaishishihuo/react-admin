# 与后端对接（设施契约）

开工前和后端对齐的是**整站共用的字段名和形状**。对不齐，壳、菜单、列表都会系统性对不上。

**要对齐**：信封、鉴权、用户 identity、菜单节点 + `handle`/`meta`、分页、主键类型。

**不要在这一轮对齐**：某个业务表有哪些列（姓名、金额、状态枚举值等）。那是各业务接口自己的 DTO。

默认值是本模板已经实现的约定。不一致只改 `src/services/http` 和 `src/features/*/api.ts`。加页见 `docs/ROUTING.md`。

---

## 1. 接口返回格式

所有 JSON 接口同一套信封，前端只把 `data` 交给业务。

```ts
{
  code: number;
  msg: string;
  data: T;
}
```

| 项       | 本模板默认                         | 必须拍板                   |
| -------- | ---------------------------------- | -------------------------- |
| 成功     | `code === 200`（数字，不是 `"0"`） | 成功码类型和值             |
| 失败提示 | `msg`                              | 字段名                     |
| 业务数据 | `data`                             | 不要把列表直接放在根上     |
| 未登录   | `code === 401` 或 HTTP 401         | 用业务码还是 HTTP 状态     |
| HTTP     | 2xx 仍要看 `code`                  | 不要只靠 HTTP 200 表示成功 |

---

## 2. 鉴权与用户

| 项       | 本模板默认                                        | 必须拍板                      |
| -------- | ------------------------------------------------- | ----------------------------- |
| 鉴权头   | `x-access-token: <token>`                         | 是否改成 Bearer               |
| 登录     | `POST /login` → `{ token, refreshToken? }`        | 字段名；有无续签              |
| 当前用户 | `GET /user/info` → `{ id: string, name: string }` | **`id` 稳定**，用来判断换用户 |
| 续签     | `POST /refreshToken` → `{ token, refreshToken }`  | 不提供则登录不要返回 refresh  |
| 登出     | `POST /logout`；401 清会话时前端不调              | 是否需要服务端登出            |

## 3. 菜单：节点 + meta 字段（dynamic）

`static` 不请求菜单。`dynamic` 为 `GET /menu/list`。

`data` 为树，或 `{ routes: Node[] }`。`handle` 与 `meta` **同一套字段，二选一**。前端**不读** `home`。

### 节点

| 字段                                 | 必须拍板                                   |
| ------------------------------------ | ------------------------------------------ |
| `path`                               | 绝对路径。动态段 `:userId`，不要 `$userId` |
| `children`                           | 树形；父级 `path` 也必须对得上前端文件     |
| `name`                               | 仅当 `handle.title` 为空时当标题           |
| `element` / `component` / `redirect` | **前端忽略**。不要用它们指定页面或授权     |

**path 约束（设施，不是业务）：** 每一项（含分组父级）必须能对上前端已有路由。对不上则整节点连 children 丢掉，打开子页 403。分组 `/list` 要求前端有 `/list` 这条路由（通常 `layout.tsx`），不能只建子页。`handle.url` 不会在没有本地文件时自动改挂到 `/iframe/$url`。

### `handle` / `meta`（开工把字段名定死）

这些是壳要用的设施字段，不是某张业务表。叫 `handle` 还是 `meta`、下面这些键叫什么，必须前期定好。

| 字段       | 本模板键名        | 作用                                 |
| ---------- | ----------------- | ------------------------------------ |
| 标题       | `title`           | 侧边栏、Tab                          |
| 图标       | `icon`            | iconify 名，如 `ri:apps-line`        |
| 不进侧边栏 | `hideInMenu`      | 详情仍可授权进入                     |
| 页面缓存   | `keepAlive`       | Tab 切走再回来是否保留实例           |
| 多 Tab     | `multiTab`        | 每个完整 URL 一个标签                |
| 高亮菜单   | `activeMenu`      | 隐藏页高亮哪条 path                  |
| 外链       | `href`            | 仅 `http(s)://`                      |
| 内嵌页     | `url`             | 仅 `http(s)://`；页面自己渲染 iframe |
| 排序       | `order`           | 同级                                 |
| 固定 Tab   | `fixedIndexInTab` | 有值则不可关闭                       |
| 按钮码     | `buttons`         | `string[]`，与后端鉴权码一字不差     |

未下发的键当未配置（`keepAlive` 未写 = Tab 不缓存）。菜单按账号滤好再下发，前端不再按角色名滤。

## 4. 列表分页

标准列表（ProTable）整站同一套，不要每个接口一套。

| 方向 | 本模板默认              | 必须拍板                             |
| ---- | ----------------------- | ------------------------------------ |
| 请求 | `page`（从 1）、`limit` | 是否 `current` / `size` / `pageSize` |
| 响应 | `{ list, total }`       | 是否 `records` / `rows` / `count`    |

搜索、排序参数跟各业务走，不在设施里定。主键、时间建议 string。

---

## 5. 同类还要确认

和信封、分页、菜单 meta 同一类：定一次、整站用。

| 设施         | 本模板默认                          | 为什么要提前定                       |
| ------------ | ----------------------------------- | ------------------------------------ |
| 主键         | **string**                          | Java Long 用 number 会丢精度         |
| 布尔         | JSON `true` / `false`               | 不要有的接口 `0/1`、有的接口 boolean |
| 时间         | 字符串，列表日期 `YYYY-MM-DD`       | 时区、时间戳秒/毫秒混用会全站错      |
| 按钮码       | 菜单 `buttons` 与接口鉴权同一字符串 | 前端 `BUTTONS.add` 对的就是这个码    |
| 批量删除     | body `{ ids: string[] }`            | 设施级写操作形状，避免每页不同       |
| 文件下载失败 | 仍走上面的 JSON 信封                | 前端按信封提示，不要只回裸 HTTP      |

业务对象有哪些字段（客户名、合同金额等）等做到那个模块再定。
